# Sunshine Game Streaming — Windows host on elitemini2

## TL;DR

- **Stream host:** `elitemini2` (10.0.0.74), booted into Windows 11 Pro 23H2 on `nvme0n1p3`
- **Client:** MacBook Pro (M3 Max) via Moonlight over LAN
- **Flow:** Mac Moonlight → Sunshine service on Windows → AMD AMF hardware encoder on Radeon 760M → H.265 stream
- **Scope:** bare-metal Windows (not a VM). Dual-boot with the Ubuntu k3s-worker install on `nvme0n1p5`. When Windows is up, the k3s-worker is down and vice versa.

## Why bare-metal, not VM

Tried GPU-passthrough on a Windows KVM VM under the Ubuntu side. Hit a self-inflicted boot failure on the host (kernel cmdline change — see "Postmortem"), walked the physical recovery, and since Windows booted cleanly on the metal anyway we pivoted. Bare-metal avoids the EAC-in-VM risk entirely (Sea of Thieves was the use case of record) and eliminates the AMD iGPU passthrough finickiness on Phoenix APUs.

**Cost of the pivot:** dual-boot means the k3s worker role on elitemini2 is unavailable whenever the host is in Windows. What pauses during Windows sessions:

- Prometheus / Alertmanager / Grafana (monitoring gap, no alerts)
- ArgoCD `application-controller` + `server` (reconciliation paused; existing desired state on other nodes keeps running)
- Platform API + Dashboard, codegen, AI gateway router/admin (v0-clone; already lower-priority per the Dec 2025 infra eval)
- Qdrant (RAG vector DB for OpenWebUI `personal_docs` / `homelab_docs` collections)
- Redis (automation cache), cert-manager, pgadmin, redis-insight

elitemini control plane, Traefik ingress, Gitea, PostgreSQL, OpenWebUI, and LocalAI on the Jetsons are unaffected.

## Remote OS toggle (no walking)

```bash
# From Ubuntu -> boot Windows once (BootOrder unchanged):
ssh elitemini2 "sudo efibootmgr -n 0000 && sudo reboot"

# From Windows PowerShell (admin) -> boot Ubuntu once:
# Look up the Linux firmware entry GUID:
bcdedit /enum firmware
# Then:
bcdedit /bootsequence '{<linux-firmware-GUID>}'
shutdown /r /t 0
```

Alternative from Windows: tap F11/F7 at the Minisforum BIOS splash to pick a boot target (requires console access).

## Host-side install summary

Everything below was done over SSH from the Mac after enabling OpenSSH Server and seeding `C:\ProgramData\ssh\administrators_authorized_keys` with the Mac's `~/.ssh/id_ed25519.pub`. The reusable setup script is at `scripts/sunshine/setup-windows-host.ps1`.

| Step | What landed |
| -- | -- |
| OpenSSH Server | `Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0`, service auto-start, firewall LAN-scoped (22/tcp from 10.0.0.0/24) |
| Network profile | Both Ethernet adapters → `Private` (was `Public`) |
| Sunshine | v2025.924.154138 installed silently via `/S`; runs as `SunshineService` (auto-start). Installer default firewall rules removed, replaced with LAN-only rules on 47984/47989/48010 (tcp) and 47998-48000/48002/48010 (udp). Web UI on 47990. |
| Sunshine admin credentials | Set via `sunshine.exe --creds admin <pw>` CLI (generated by `System.Web.Security.Membership::GeneratePassword`). Stored in `C:\Program Files\Sunshine\config\sunshine_state.json`. |
| Sunshine apps.json | Default has `Desktop` + `Steam Big Picture`. Added `Sea of Thieves` entry with `cmd: steam://rungameid/1172620` and `undo` prep-cmd to `taskkill /im SoTGame.exe`. |
| Steam | Installed via direct `SteamSetup.exe` download (Akamai CDN, silent `/S`). Default path `C:\Program Files (x86)\Steam\steam.exe`. `steam://` URI handler registered in HKLM. |
| AMD driver | Factory Adrenalin `32.0.12011.4002` (Oct 2024). AMF HEVC encoder present. **`HypervisorPresent=False`** — Memory Integrity / VBS off, so AMF capture runs at full HW speed. Not touching the driver until we see problems. |

## Pair Moonlight from the Mac

Install Moonlight (Mac App Store or https://moonlight-stream.org). Then:

1. Launch Sunshine web UI: `https://10.0.0.74:47990` — self-signed cert, accept the browser warning.
2. Log in with `admin` / (password stored in your password manager — see post-install handoff message).
3. Top-right: **PIN** → click **Generate** → 4-digit PIN appears.
4. On Mac Moonlight, **+ Add PC** → type `10.0.0.74` → when prompted for PIN, type the 4-digit code from step 3.
5. Moonlight shows three apps: **Desktop**, **Steam Big Picture**, **Sea of Thieves**. Pair test: launch **Desktop** first.

Good paired stream: 1080p60 default, encode latency in Sunshine logs should be `<5 ms` on AMD AMF HEVC.

## Adding a new game later (runbook)

Edit `C:\Program Files\Sunshine\config\apps.json` (requires admin). Add a new entry to the `apps` array of the form below, then `Restart-Service SunshineService`. Moonlight will show the new app on next refresh. Use the Steam AppID from the game's store URL (`store.steampowered.com/app/<ID>/...`).

```json
{
  "name": "<Game name>",
  "cmd": "steam://rungameid/<AppID>",
  "prep-cmd": [
    { "do": "", "undo": "cmd /c taskkill /im <GameExe>.exe /f 2>nul & exit 0" }
  ],
  "auto-detach": true,
  "wait-all": true,
  "image-path": "steam.png"
}
```

Non-Steam launchers (EGS, Battle.net, direct exe): `cmd` can be a full path to the launcher or the game binary. See Sunshine docs: https://docs.lizardbyte.dev/projects/sunshine/

## Sea of Thieves — first-time setup

1. On the Windows host (console or RDP), open Steam, sign in with your Steam account (I have not and will not touch these creds).
2. Install Sea of Thieves (AppID 1172620). ~120 GB, will take a while.
3. Once installed, Moonlight → Sea of Thieves → game launches, EAC should initialize cleanly on real hardware.

Sunshine only captures the active console session. If Windows locks the screen, the stream shows the lock screen, not the desktop. Either leave the session unlocked while streaming, or disable screen lock under Settings → Accounts → Sign-in options → "If you've been away, when should Windows require you to sign in again?" = Never.

## Postmortem — Ubuntu side is currently broken

The Ubuntu boot partition's GRUB cmdline was edited with `amd_iommu=on iommu=pt video=efifb:off` for the (aborted) VM-passthrough plan. `video=efifb:off` prevents Ubuntu from booting on this Minisforum EliteMini firmware (early boot hang before console output). Windows boots fine because EFI fell through to the next bootable entry.

**To recover Ubuntu (one-time physical access needed):**

1. Power cycle elitemini2.
2. Mash `Shift`/`Esc` at the Minisforum splash to stop GRUB autoboot.
3. Arrow to the top Ubuntu entry, press `e`.
4. Find the line starting `linux /boot/vmlinuz-...` — delete `video=efifb:off` (leave `amd_iommu=on iommu=pt` alone; they're fine).
5. `Ctrl-X` to boot.

Once it's on the LAN:

```bash
ssh elitemini2 "sudo sed -i 's| video=efifb:off||' /etc/default/grub && sudo update-grub && grep GRUB_CMDLINE_LINUX_DEFAULT /etc/default/grub"
```

Then subsequent Ubuntu boots are back to normal, and k3s-worker rejoins the cluster (`kubectl uncordon elitemini2` from the master — it was cordoned before the failed reboot and is still cordoned).

## File locations on the Windows host

- Sunshine binary: `C:\Program Files\Sunshine\sunshine.exe`
- Sunshine config dir: `C:\Program Files\Sunshine\config\`
  - `apps.json` — streamed app list (edit + restart service)
  - `sunshine.conf` — main config (empty = defaults)
  - `sunshine_state.json` — admin credentials, paired clients
  - `sunshine.log` — runtime logs including encode timings
  - `credentials/` — client pairing keys
- Steam: `C:\Program Files (x86)\Steam\steam.exe`
- Steam games default library: `C:\Program Files (x86)\Steam\steamapps\common\`
